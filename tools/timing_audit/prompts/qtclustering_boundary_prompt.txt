MEASUREMENT CONTRACT

The sequential reference generates input points before its timer, then times the
whole qtClustering call. That call calculates Euclidean distances on demand while
growing candidates and selecting clusters. The revised implementation may optimize
or precompute this work, but MUST include the replacement algorithmic computation
in the canonical reported duration. Function names such as init, setup, prepare,
constructor, or warmup do not exempt real computation from measurement.

Specifically trace the earliest computation of pairwise distances (including
squared distances), threshold/neighbor tables, spatial indexes, candidate lists,
cached candidate clusters, and other input-dependent clustering information used
by the timed algorithm. These must be timed, even if performed in a constructor,
on the CPU before a GPU kernel, or once before repeated clustering iterations.
Do not require an implementation to build a distance matrix: on-demand distance
evaluation inside the interval is equally valid. Classify concrete excluded
algorithmic preprocessing as incomplete_timed_region. Do not speculate that an
unidentified preprocessing step exists merely because an implementation is fast.

Ordinary input generation, allocation/reservation, runtime initialization, empty
warm-up work, and layout-only copies of the input may remain outside the timer.
An initialized array of coordinates or empty workspace is different from a table
of computed distances or neighbors. Extra setup timed together with the required
work is conservative, not itself a validity defect. Final validation, diagnostics,
and output-only collection may remain outside the compute interval. Conversely,
collectives or host work that advance clustering decisions belong inside it.
Review the actual full-benchmark arguments, including non-validation dispatch.
